Wx411Easy 1.5 RC9 精准捕获与一致导出说明
========================================

运行环境
--------
- Windows 10/11 x64
- 右键 EXE，选择“以管理员身份运行”
- RC9 为自包含单文件，不需要额外安装 .NET、Python 或 VC++ 运行库
- 源数据库只读；工具只在输出目录生成可读副本和证据包

界面流程
--------
- “刷新列表”：只刷新目标进程和数据库列表
- “定位 key 并解密”：唯一恢复入口，监听 key 设置事件并逐库导出
- “取消”：停止等待、监听、认证和输出，并执行断点与临时文件清理
- “导出证据包”：保存脱敏日志、哈希、完整性结果和门禁结论

推荐操作顺序
------------
1. 完全退出目标程序，包括托盘；任务管理器确认没有 `Weixin.exe`。
2. 以管理员身份启动 RC9。
3. 目标进程保持“自动捕获全部 Weixin.exe”。
4. 选择一个数据库作为 PID 优先库；列表中的全部发现数据库都会参与匹配。
5. 每轮选择新的空输出目录。
6. 先点击“定位 key 并解密”。
7. 再启动目标程序；日志出现早鸟等待时继续等待自动附加。
8. 等日志出现“Weixin.dll 已加载，已同时设置 4 个观察点”。
9. 现在登录，再访问聊天、图片、语音、视频和联系人资料页，触发实际数据库使用。
10. 保持工具和目标程序开启，等待监听和逐库导出完成。

时间与监听
----------
- 最长 5 分钟：点击主按钮时目标程序尚未启动，工具等待进程出现。
- 最长 180 秒：观察点设置后等待实际 key 事件。
- 监听期间每 500 ms 刷新数据库描述符，可发现新建 `.db` 和同路径换代。
- “数据库总数/已暂存/尚未命中”是动态计数；尚未命中不代表数据库未被发现。

一致导出
--------
- 抽样命中只进入 pending，不直接生成文件。
- 解除附加后一次处理一个数据库，校验 WAL 最后有效 commit，逐页认证、逐页解密并执行 `integrity_check`。
- 成功后原子移动正式副本，并清理临时数据库、`-wal`、`-shm` 和 sidecar。
- 一个数据库失败会记录并继续其它数据库；已完成副本保留。
- `media_0`、`bizchat` 等库需要对应业务动作触发 key 事件，文件存在不代表本轮一定命中。
- RC9 不实现关闭程序后的跨启动后台续跑。

取消与证据
----------
1. 第一轮按推荐顺序启动捕获，等观察点设置完成后点击“取消”。
2. 等界面显示“已取消”，确认输出目录无临时文件。
3. 第二轮完全退出并重新启动目标程序，再按推荐顺序捕获。
4. 输出完成后点击“导出证据包”。

门禁含义
--------
- Gate A：N/A，旧内存扫描入口已废弃。
- Gate B：至少一个可读副本通过逐页认证和 `integrity_check`。
- Gate C：取消后目录清洁，后续运行确认 DPAPI pending 票据未复用。
- Gate D：只记录源文件运行期间的变化，不参与总结果。
- Gate B 与 Gate C 均为 PASS 时，总结果为 PASS。

已验证基线
----------
- Windows 10 x64 真机：发现 18 个数据库，成功输出 13 个，5 个未触发对应业务动作。
- 输出失败 0 个；成功路径临时 `*.tmp-wal`、`*.tmp-shm` 残留 0 个。
- Gate B、Gate C 和总结果均为 PASS。
- 源文件哈希变化属于目标程序持续写入，记录为 Gate D 观察项。

常见情况
--------
- 没找到进程：先点击主按钮，再启动目标程序；工具会自动早鸟附加。
- 日志停在观察点设置：登录并访问实际内容后才会触发 key 事件。
- 日志显示“换代”：同路径数据库的长度、修改时间或文件身份发生变化，工具会刷新描述符。
- 日志显示“尚未命中”：继续访问对应业务；已命中数据库会独立导出。
- 取消后需要验证票据：第一轮取消后完全退出目标程序，再进行第二轮。
