# Windows Live2D 指针跟随桌宠设计

## 目标

制作一个独立的 Windows 桌面桌宠：以透明、无边框、默认鼠标穿透的小窗口显示全身高清 Q 版角色。角色会注视鼠标、轻微转头、呼吸、眨眼、漂浮和回弹，并保留 PNG 渲染作为 Live2D 模型不可用时的可运行回退方案。

此项目不修改 Android 应用，也不复用现有 `windows-pet-wpf` 中的聊天、语音、微信数据处理或管理员权限逻辑。

## 已确认的视觉范围

- 角色为全身高清 Q 版插画风，不沿用原图的低分辨率像素渲染方式。
- 严格保留现有角色的蓝发、异色瞳、红色发饰、流苏、服装层次和两侧装饰。
- 默认表情外，第一版包含闭眼、开心、惊讶和委屈四种表情。
- 睡觉等大姿势变化不强行制作成 Live2D 参数动画，仍作为独立 PNG 状态使用。

## 分阶段交付

### 阶段一：视觉和桌面壳

1. 以现有精灵图为视觉参考，重新制作一张 2048 × 2048 的全身高清主视觉。
2. 输出默认、闭眼、开心、惊讶、委屈五个合成预览状态，用于 PNG 模式和视觉验收。
3. 新建独立 WinUI 3 + Windows App SDK 工程 `windows-pointer-pet-winui`。
4. 实现透明无边框窗口、置顶、托盘入口、鼠标穿透、鼠标方向跟随、待机漂浮、压缩回弹和 PNG 加载。

阶段一完成后，即使 Live2D 模型尚未完成，用户也可运行完整的 PNG 桌宠。

### 阶段二：Live2D 模型与集成

1. 将角色重新组织成 Cubism 可绑定的透明部件 PNG。
2. 在 Cubism Editor 中建立网格、变形器、参数、表情和物理配置，导出 `.moc3`、`model3.json`、贴图、物理与表情数据。
3. 使用 Cubism Native SDK 和 Direct3D 11 在 WinUI 3 中渲染模型。
4. 保留 PNG 渲染器作为模型文件丢失、加载失败或显卡初始化失败时的回退。

## 素材结构

原始精灵图只作为参考，不能直接转换为 Live2D 模型。新的模型源素材必须补齐遮挡区域，并使用一致的画布、锚点和透明边缘。

建议结构如下：

```text
Assets/Live2D/
  reference/                 # 原始精灵图，仅作视觉参考
  source/
    body/
    face/                    # 脸底、鼻子、嘴巴
    eyes/                    # 左右眼白、虹膜、瞳孔、高光、上下眼皮、眉毛
    hair/                    # 前发、侧发、后发、发梢、呆毛
    costume/                  # 上衣、裙摆、袖子、双手、双腿
    ornaments/                # 花饰、流苏、两侧装饰
  preview/                   # 五个 PNG 合成预览状态
  model/                     # Cubism 导出的运行时文件
```

角色主体与各个部件以透明 PNG 保存；Cubism 可直接导入这些部件。主视觉和预览图不替代可编辑部件源文件。

## 桌面端架构

```text
WindowHost
  ├─ PointerTracker        获取鼠标位置并完成 DPI/多屏坐标转换
  ├─ MotionController      死区、方向滞回、弹簧平滑与待机节奏
  ├─ ClickThroughController
  │    └─ WM_NCHITTEST 返回 HTTRANSPARENT；拖动模式时恢复正常命中测试
  ├─ PetRenderer
  │    ├─ PngRenderer      阶段一和故障回退
  │    └─ Live2DRenderer  Cubism Native SDK + Direct3D 11
  └─ TrayController        显示、拖动模式、退出等可达入口
```

`PointerTracker` 读取 `GetCursorPos` 后，先转换成当前窗口的本地坐标，再交给 `MotionController`。因此不同显示器缩放比例和窗口跨屏时不会因物理像素与 WPF/WinUI 逻辑单位混用而误判方向。

## 动画与参数映射

- 指针相对桌宠中心的位置映射为 `-1…1` 的目标向量。
- 中心死区内维持当前方向；八向边界使用滞回，避免指针在边缘时抖动。
- 通过基于 `deltaTime` 的弹簧平滑目标值，产生受控的小幅过冲，且快速来回移动时可收敛。
- 目标值映射到 Live2D 的 `EyeBallX/Y`、`AngleX/Y/Z`。
- 呼吸、眨眼、头发和流苏物理由独立待机时钟驱动；鼠标静止时降低方向更新频率，渲染仍按显示器刷新节奏推进。
- 漂浮、缩放回弹、轻微摇摆和投影变化由 Windows Composition 驱动；大姿势状态切换时优先使用独立 PNG。

## 窗口行为与隐私

- 默认无边框、透明、始终置顶、不可在任务栏显示、不会激活或抢焦点。
- 点击穿透通过窗口命中测试实现；进入“拖动模式”后恢复命中测试以移动桌宠，退出后立即重新穿透。
- 鼠标位置仅用于当前帧计算，不写入文件、不上传、也不读取屏幕内容。
- 本版本不含网络、语音、屏幕识别、全局热键、开机自启或多宠物管理。

## 失败处理

- 缺少或加载失败的 Live2D 文件：记录本地诊断信息并自动使用 `PngRenderer`。
- Direct3D 初始化失败：自动使用 `PngRenderer`，不阻止应用启动。
- 跨屏、DPI 或窗口句柄变化：重新获取坐标转换信息并继续沿用上一有效方向。
- 无法进入拖动模式：仍可通过托盘菜单显示或退出应用。

## 验收标准

- Windows 100% 和 150% 缩放、单屏和双屏环境下，指针方向始终正确且稳定。
- 桌宠可在任意位置显示；默认状态不阻挡对桌面及其他应用的鼠标点击。
- 左、右、上、下和四个斜向的目标方向在 150–250 ms 内完成视觉过渡；快速来回移动时不闪烁、不持续抖动。
- 60 Hz 显示器上，待机、转头与回弹无肉眼可见卡顿；空闲时 CPU 占用保持低。
- 模型可用时，眼神、轻微转头、呼吸、眨眼和饰品物理正常工作；模型不可用时 PNG 模式可独立启动。
- 角色的默认、闭眼、开心、惊讶与委屈表情可被正确呈现。

## 非目标与前置条件

- 不实现 Live2D 模型编辑器、语音识别、网络同步、屏幕读取、鼠标轨迹记录或 Android 改造。
- Cubism SDK 与角色素材在分发前必须完成相应的授权核对。
- Live2D 成品依赖高分辨率分层角色稿及 Cubism Editor 绑定；不能由现有合成精灵图自动恢复。
