# Windows 后台自动恢复与网页监控闭环设计

日期：2026-07-26
目标版本：1.0.15
状态：用户已批准方向，等待书面规格复核

## 背景与根因

1.0.14 的两个 Worker 能够启动，但 Recovery 只检查当前用户 `Documents/xwechat_files` 与系统“我的文档”下的同名目录。云电脑的数据位于其他盘符、重定向目录或 `Weixin Files`、`WeChat Files` 等位置时，`WeChatIdentityProvider.ResolveActive` 在进入捕获器之前返回 `target_not_running_or_data_root_unavailable`。

因此本次现象不是密钥已提取但验证失败，也不是数据库已经开始解密后失败，而是数据根目录解析失败导致密钥捕获、两次重启预算和解密流程都没有开始。该等待结果没有形成 Recovery 遥测，DataSync 又没有生产代码初始化 `server-settings.dpapi`，所以心跳和事件停留在本地 Outbox，后端网页没有任何日志。

用户本次账号发现的 18 个数据库只是该账号、该微信版本和该时刻的实际样本，不是产品常量或通过门槛。不同账号会因功能使用、历史数据、分库数量和版本差异而拥有不同数量的数据库。

两个 Worker 当前还以控制台 `Exe` 发布，在交互式计划任务下会显示黑色窗口。这不影响进程启动，但不符合静默后台运行要求。

## 用户体验决策

- 桌宠界面保持原样，不增加“后台状态”页面、弹窗或常驻提示。
- 所有运行状态只显示在现有后端网页。
- 用户不需要命令行、任务计划程序或手工寻找 `%LOCALAPPDATA%`。
- Worker 改为静默后台程序，但保留供自动测试和诊断包调用的机器可读诊断能力。

## 架构边界

- Recovery 独占微信进程观察、数据目录发现、密钥捕获、最多两次静默重启、密钥复用、数据库解密和 generation 发布。
- DataSync 独占服务器配置、稳定客户端身份、Parser、加密 Outbox、心跳、遥测导入和 HTTP 上传。
- Parser 只读取 Recovery 发布的可读数据库，不接触进程、密钥、token 或网络。
- WPF 只负责请求启动两个固定后台任务，不读取密钥、不上传状态、不监管 Worker。
- 远程发布分支和安装包继续排除整个后端源码；本轮不恢复或修改主工作树中的 `server/`。客户端只复用已部署的 `/api/status`、`/api/events` 和现有网页事件映射。

## 数据目录自动发现

新增独立的 `WeChatDataRootLocator`，按以下顺序生成候选目录：

1. 读取旧实现已经支持的微信配置目录来源。
2. 当前用户、系统文档、OneDrive 与用户配置环境目录。
3. `Weixin Files`、`WeChat Files`、`xwechat_files` 三类目录名。
4. Windows 可用固定盘和云电脑附加盘上的有限深度结构匹配。
5. 上次成功根目录；存在且结构仍有效时优先复用。

候选目录以账号目录为边界，必须包含符合新版结构的 `db_storage/session`，并通过 `session.db`、`message*.db`、最近写入时间和当前进程活动信号评分，从多个账号目录中选出当前活动账号。只监控最终选中的账号数据根目录，避免长期递归扫描所有盘。五分钟 reconciliation 或已选目录失效时重新定位；新候选只有在活动信号明确更高时才替换当前根目录。

数据库集合始终动态生成：发现当前账号目录下符合加密数据库特征的实际 `.db` 文件，并随数据库新增、换代、分片或暂时不可用而更新。实现不假定固定数量，不补齐不存在的库，也不因数量不是 18 而判定失败。

目录发现过程产生脱敏状态：扫描候选数、有效根目录数、数据库数和稳定错误码。绝对路径不进入遥测。

## 密钥捕获与解密状态

Recovery 在进入每个阶段前后发布状态变化。为兼容已经部署的网页，本轮复用现有事件名，不引入需要同步发布后端代码的新事件名：

- `client_v4_data_dir_result`：表示等待目标、目录发现成功或目录未发现，具体结果使用稳定 code 与计数区分。
- `recovery_capture_started`
- `recovery_capture_succeeded`：`code=key_validated` 表示密钥已验证。
- `recovery_capture_failed`
- `recovery_restart_started`
- `recovery_restart_completed`
- `recovery_circuit_opened`
- `client_wechat_decrypt_export_result`：表示数据库解密成功数与待补齐数。
- `recovery_handoff_published`

状态只携带数据库数、成功数、待补齐数、重启次数、版本和稳定错误码。密钥内容、票据内容、完整路径、内存数据和原始异常文本不进入事件。

首次实时捕获失败后沿用现有状态机，最多静默重启微信两次。两次仍未取得可验证密钥时打开持久熔断，不再无限重启。已有验证密钥继续用于新数据库补齐；数据根目录暂时消失不会清空密钥 vault，也不会消耗重启预算。

## 服务器配置启动引导

DataSync 启动时在创建首条心跳前执行一次幂等 bootstrap：

1. 优先打开现有 DPAPI 设置。
2. 缺失时迁移 `WECHAT_MONITOR_SERVER_URL`、`WECHAT_MONITOR_SERVER_TOKEN` 或旧监控配置。
3. 仍缺失时使用当前部署已有的默认服务器地址和 token。
4. 校验 HTTPS origin 和 token 后写入 CurrentUser DPAPI 文件。

任何来源中的 token 都不写日志、不进入命令行、不传递给 Parser。损坏的 DPAPI 文件保留证据并以稳定错误码上报到本地诊断；bootstrap 使用有效的迁移来源重新生成设置。

## 纯网页可观察性

DataSync 启动后立即创建持久状态心跳，此后每 60 秒更新一次。现有 `/api/status` 表示当前快照，`/api/events` 表示状态变化时间线。

网页能够观察以下信息：

- Recovery 与 DataSync 是否在线及最后心跳时间。
- 微信进程为等待、已发现或已退出。
- 数据根目录发现是否成功以及候选数据库数量。
- 密钥为等待触发、捕获中、已验证、两次失败熔断。
- 数据库解密成功数、待补齐数和 generation 发布时间。
- Parser 完成、失败与导出条目数量。
- Outbox 待上传数、最后成功上传时间、HTTP 状态和稳定错误码。

后端超过 120 秒未收到心跳时，将该客户端视为离线。网络中断时事件和最新状态保存在加密 Outbox；恢复联网后按原 request ID 续传并保持幂等。状态心跳继续合并，只保留一条最新未租赁状态，避免离线期间无限增长。

Recovery 必须在目录发现失败和目标未启动时也生成兼容遥测文件。这样用户尚未登录微信时，网页仍能通过心跳和目录识别事件显示“后台在线，等待微信”，而不是空白。

## 静默运行与本地诊断

Recovery Worker 和 DataSync Worker 发布为 Windows `WinExe`，计划任务启动时不显示控制台窗口。`--diagnose` 继续输出 JSON，供自动化、安装包自检和一键证据包使用；普通用户不需要直接运行它。

每个 Worker 原子维护一份不含秘密的本地运行快照。WPF 不展示该快照；证据收集器可读取快照、SQLite 计数、任务激活记录和发布清单，生成单个诊断包。

## 错误处理

- 未找到微信进程：被动等待并持续心跳，不消耗重启预算。
- 未找到数据根目录：有限深度重新发现并上报稳定错误码，不进入捕获器。
- 捕获未验证密钥：记录阶段结果，按最多两次重启规则推进。
- 已有密钥但部分数据库失败：发布成功输出，保留待补齐项并后台续跑。
- 服务器配置损坏：从受支持来源重新 bootstrap；Outbox 保持不丢失。
- 网络或后端暂时失败：指数退避并续传；业务、状态和事件使用原 request ID。
- Worker 意外退出：计划任务有限次数拉起；本地状态库和恢复预算继续沿用。

## 测试策略

### 自动测试

- 数据根目录定位覆盖默认文档、重定向文档、OneDrive、其他固定盘、附加盘、三类目录名、多账户候选评分和目录换代。
- 目录缺失时证明捕获器未调用、重启预算未消耗且失败结果已通过 `client_v4_data_dir_result` 持久发布。
- 分别包含不同数据库数量的 fixture 都能进入 RC9 捕获适配器；其中 18 库 fixture 仅用于回归本次账号样本，不作为固定阈值。
- 已验证密钥可解密成功子集并保留待补齐数据库；Worker 重启后继续。
- 设置 bootstrap 覆盖已有 DPAPI、环境迁移、旧配置迁移、部署默认值、损坏设置恢复和并发幂等。
- 无设置、断网、超时、HTTP 重试和进程重启期间 Outbox 不丢失。
- 心跳合并、事件幂等、两分钟离线判定所需字段和网页既有事件映射均通过客户端契约测试；测试从本地 fixture 固化已部署接口的请求与响应形状，不将后端源码带入发布分支。
- 两个 Worker 的普通入口不创建控制台窗口，诊断入口仍返回有效 JSON。
- 原有 Recovery、DataSync、Parser、WPF、安装器和卸载器测试保持通过。

### Windows 真机验收

1. 全新云电脑安装后不出现两个 Worker 黑色窗口。
2. 不启动微信时，90 秒内网页出现后台在线和等待微信状态。
3. 启动并登录微信后，网页显示当前账号的实际数据库发现数并进入密钥捕获阶段；数量可以少于或多于 18。
4. 成功捕获后显示密钥已验证、解密成功数、待补齐数、Parser 结果和上传成功。
5. 捕获失败时最多静默重启两次，网页显示次数和熔断状态。
6. 断网后产生状态，恢复网络后网页补齐事件且不重复业务记录。
7. 覆盖安装保留 DPAPI 设置、已验证密钥、恢复预算、generation 和 Outbox。

## 发布门禁

- 版本统一提升到 1.0.15。
- CI 完整测试、Release 构建和安装包静态检查通过。
- 安装包不包含后端源码、旧扫描器、旧监控器或重复 .NET Runtime。
- 发布清单、安装包 SHA-256 和大小均核验。
- 真机网页首先出现心跳，再验证真实数据库发现、密钥捕获、解密、解析和上传；仅看见 Worker 进程不再计为通过。
